# RuTracker title corpus + expected parse results
# (sampled 2026-11-17 from live tracker.php listings)
#
# HOW THIS CORPUS WAS BUILT
# 1. Live titles were sampled from the tracker.php topic listings of 14 series
#    forums (6 SD: f=9,33,235,242,842,921 and 8 HD: f=81,193,266,625,1171,1669,
#    1803,2393) - newest 100 + oldest 250 topics per forum. The raw sample is
#    3207 rows; after removing exact duplicates (71 rows where the same topic
#    landed in both sampling windows) it holds 3136 unique topics spanning
#    2005-2026. A further ~290 rows are re-releases of the same show in
#    different quality - real, distinct topics.
# 2. The sample was clustered by wording template (title shape: "Сезон: N /
#    Серии: a-b из N", "(N)" totals, word style "a-b серии из b", etc.).
# 3. From every template cluster, representative titles were picked across the
#    2005-2026 spread, plus the template examples quoted in the official
#    pinned rules topics. Every entry below is a REAL sampled topic title
#    (except the rules-template examples, which are also real topics).
# 4. The expected result of every title was written and verified BY HAND.
#
# Data file: real topic titles, one per line. A `# expect:` comment DIRECTLY
# AFTER a title declares what the pipeline SHOULD yield for it:
#
#   # expect: seasons=1-5            season range 1..5 (or seasons=1,2 list)
#   # expect: season=3               single season
#   # expect: eps=1-32               episode range within the season
#   # expect: total=32               stated episode total ("из N" / "(N)")
#
# What is checked: apply the rutracker.yaml title filters to the title, call
# parseRelease on the result, and compare against the expect line. For
# multi-season expectations (seasons with more than one entry) only the
# seasons aspect is compared - EpisodeInfo holds either a seasons list or a
# single season + episodes, never both. The companion file
# rutracker-corpus.test.ts (same folder) does exactly this with the project's
# own test runner:
#
#   npx vitest run rutracker-corpus.test.ts
#
# BEHAVIOUR MARKERS (as of 2026-11-17, stock rutracker.yaml + parser):
#   [BUG-MS]   multi-season collapsed to S1 (YAML PHASE 1 loses the range; the parser alone handles it)
#   [BUG-EP]   season-less "Серии: a-b из N" loses episodes and season-pack status entirely
#   [BUG-TOT]  "(N)" / "из N" total not propagated to episode total / isCompleteSeries
#   [BUG-WORD] word style "a-b серии из b" not parsed at all
#   [OK]       parses correctly today (regression guard: must keep working)
